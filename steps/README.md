# 分步工作流 / Step-by-step workflow

这套 Skill 把一次内容任务拆成八个可恢复步骤。每一步都有明确输入、输出和闸门；可以从头运行，也可以从已有状态继续。步骤文档只描述决策和交接，具体命令与平台细节仍放在 `references/` 和 `modules/`。

## 主链路

```text
01 内容成形
  -> 02 素材接收与建档
  -> 03 粗剪与工作片
  -> 04 音频、字幕与质量检查
  -> 05 视觉设计与预览
  -> 06 正式导出
  -> 07 发布包、上传与发布
  -> 08 发布登记与复盘
```

| 步骤 | 文档 | 输入 | 主要输出 | 通过条件 |
|---|---|---|---|---|
| 01 | [content.md](content.md) | 想法、经历、草稿或数据 | 定稿、拍摄稿、预测记录 | 事实、判断和推断分开，核心主张明确 |
| 02 | [intake.md](intake.md) | 原片、脚本、账号信息 | 任务目录、状态、素材清单 | 原片只读，比例和音频可用 |
| 03 | [edit.md](edit.md) | 有序原片 | EDL、工作片 | 没有未处理的语义歧义 |
| 04 | [caption-and-qa.md](caption-and-qa.md) | 工作片 | 词级字幕、音频处理、QA 报告 | 字幕跟随最终工作音频，安全区和解码通过 |
| 05 | [design-and-preview.md](design-and-preview.md) | 工作片、字幕、设计需求 | DESIGN、可审预览 | 视觉元素不遮挡证据，用户可审阅 |
| 06 | [export.md](export.md) | 已批准预览 | 唯一正式成片 | 完整解码、音视频和元数据通过 |
| 07 | [package-and-publish.md](package-and-publish.md) | 正式成片、标题、封面 | 平台清单、上传结果、发布结果 | `final_ready`，当前发布权限和批准闸门都满足 |
| 08 | [retro.md](retro.md) | 发布登记、平台数据 | 复盘、下一轮可验证改进 | 只把确认过的结论写回校准资料 |

## 断点恢复

优先读取任务目录中的 `.creator-workbench.json`、`.naive-video-state.json` 或平台清单，再读取当前步骤文档。聊天记录不能替代状态文件。发现状态和文件不一致时进入只读诊断，保留现场，不重复上传或覆盖原片。

## 模块边界

- `content` 只负责内容判断和校准，不渲染视频。
- `editing` 负责素材、剪辑、字幕、设计、预览和导出，不推断发布授权。
- `publishing` 负责清单、上传、提交和结果核验，不修改原片。
- `retro` 只写入已核验的发布事实和明确反馈，不把一次未确认偏好升级为永久默认。
