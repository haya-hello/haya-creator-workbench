# 自动真人剪辑

把复杂真人剪辑流程收束为“素材输入 → 一个正式成片”。本 Skill 编排现有 `talking-head-video-pipeline`，不复制渲染器或另建视频项目。

## 正式入口

- 生产运行时：本仓库 `runtime/remotion`
- 任务目录：用户工作区 `jobs/<平台账号>/<日期-主题>/`
- 基础 Skill：本仓库 `modules/talking-head-video-pipeline/SKILL.md`
- 新任务脚本：`scripts/new-auto-talking-head-job.ps1`

开始任务时必须完整读取基础 Skill；按其路由读取粗剪、字幕、设计、导出、状态和质量闸门参考。不要把本 Skill 当作绕开质量闸门的快捷渲染命令。

## 真人剪辑台分流

先按“执行渠道、当前操作、版式配置”三层路由。完整规则见 [references/workbench-routing.md](references/workbench-routing.md)。

- 执行渠道：用户在 Codex 直接给素材时为 `codex-direct`；只有明确要求从网站上传或测试网站时才为 `web-upload`。
- 当前操作：新原片自动直出使用本 Skill；已有任务返修使用 `talking-head-video-pipeline`；参考效果先进入 `reference-effect-lab`。
- 版式配置：自动探测实际显示比例，`9:16` 使用 `portrait-9x16`，`16:9` 使用 `landscape-16x9`；混合或其他比例停止确认。

初始化必须生成任务根目录 `.talking-head-workflow.json`。开始剪辑或返修前先使用 `scripts/Set-TalkingHeadWorkflowLock.ps1` 写入本次实际渠道，再读取并报告工作流指纹；锁文件分别保留首次建任务的 `origin_channel` 与当前操作的 `active_channel`。状态为 `blocked` 时不得继续，也不得回退通用视频 Skill。

## 用户只需提供什么

最低输入是一段或多段按拍摄顺序排列的真人口播视频。除非材料混合比例、顺序无法判断或语义删减存在歧义，否则不要要求用户再解释技术参数。

默认值：

- 顺序：按用户列出的顺序；只给目录时按文件名自然升序。
- 比例：读取编码尺寸、旋转元数据和代表帧后保持源片实际显示比例，不擅自改成 9:16 或 16:9。
- 语义去重：重复或未说完后重说时，保留后一次完整表达。
- 气口：自然口播档，不吞字；剪点使用约 3ms 音频淡化。
- 字幕：来自获批工作片的本地词级转写，优先使用可用的高精度模型；参考稿只校正专有名词、明显同音错字和语义断句。必须人工复核错字、漏字、专有名词、词中断句、闪烁、重叠和安全区，字号使用用户当前偏好的较大可读样式。
- 动效：默认 `none`，只保留静态字幕；用户当次明确说“加动效”时才切换为 `calm`、`balanced` 或 `energetic`，并按真人安全区执行。
- 人声：`talk-clean`，只做轻度前置和响度统一，不默认强降噪、强去齿音。
- 倍速：1.0；用户明确要求时才改为 1.1。
- 输出：只保留一个平台通用正式成片；不默认生成母版、上传版和整片低清预览。

## 工作流

### 1. 建立可恢复任务

先运行新任务脚本。示例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\modules\auto-talking-head-editor\scripts\new-auto-talking-head-job.ps1" `
  -MaterialPath "D:\path\clip-01.mp4","D:\path\clip-02.mp4" `
  -JobPath "D:\creator-workspace\jobs\my-account\2026-09-11-topic" `
  -EntryChannel "codex-direct"
```

脚本只登记原片、探测显示比例并创建 `edit/`、`preview/`、`final/`、`qa/`、流水线状态和工作流锁；不改动、不复制、不转码原片。先用 `-PlanOnly` 可只读检查。网站入口必须显式使用 `-EntryChannel web-upload -InitializeExisting`，不能沿用 Codex 直剪默认值。

### 2. 先探测，再决定时间轴

对每个源片核验：

- 编码宽高、旋转/display matrix、实际显示宽高和比例；
- 帧率、时长、音频流；
- 开头、中间、结尾代表帧；
- HEVC 随机寻帧和长解码稳定性。

混合比例或旋转信息与代表帧冲突时停止，不得猜。稳定源片直接使用；只有解码不稳定才建立一个高质量工作底片，并在状态中记录理由。

### 3. 生成语义粗剪 EDL

先对原片逐段本地转写，再生成 `edit/rough-cut-edl.json`。EDL 必须同时记录：源片、保留区间、被排除的重复文本、采用后拍版本的理由、气口参数、歧义列表和预期时长。

处理规则：

1. 先按口述和拍摄顺序串联。
2. 相邻片段出现相同开头或前一段未完成、后一段完整重说时，保留后一完整版本。
3. 只因措辞相近但结论不同，不得自动删。
4. 高置信度的明确重说可自动应用；`ambiguous_cuts` 非空时只给用户看这些争议项，确认后再继续。
5. 在词尾或静音边界剪切，不能只依据固定分贝阈值批量吞掉短音节。

EDL 结构与验收项见 `references/pipeline-contract.md`。

### 4. 只构建一个获批工作时间轴

将语义删除与自然气口合并为同一份 EDL，再生成一个工作片。禁止先生成“去气口版”、再生成“删重版”、再生成“增强版”三个可交付视频。中间段文件只能作为可删除缓存，不能冒充成片。

### 5. 以主音频为唯一时间基准

在最终工作时间轴确定后：

1. 对工作片做 `talk-clean` 人声增强；
2. 对增强后的同一时间轴运行本地 Faster-Whisper 词级转写；
3. 保留人工校正文字，但用真实首词和末词时间重建字幕；
4. 默认不生成动效；用户当次明确要求动效时，动效只引用这组字幕的语义锚点，不另抄手写秒数；
5. 如使用 1.1 倍速，只在一个映射函数中统一换算画面、音频、字幕和可选动效。

声音、字幕以及用户明确要求的动效，任一使用不同时间源都判定失败。

### 6. 默认字幕-only；动效必须显式启用

新任务不得自动生成卡片、标题条、进度线、文字动画、转场或其他视觉动效。只有用户在当前任务明确要求加动效时，才从现有动效库按内容选择结构，并遵守：

- 开场、转折、数据、对比、流程、总结分别使用合适的语义模板；
- 主动效与辅助动效错峰，进入、展开、强调、退出都有变化；
- 大气但不挡脸，元素分布向两侧，字幕安全区保持清晰；
- 展示操作时可切为大面积录屏或证据画面，并把真人放入左下圆形框；没有信息或动画价值的装饰不要常驻；
- 9:16 与 16:9 分开排版，不直接缩放复用。

### 7. 轻量预览与质量闸门

默认启动 Remotion Studio，输出代表帧和必要的同步检查短片；不编码整条低清预览。只有用户明确要求完整预览文件时才生成。

至少检查：

- 重复重说已删除且没有误删新信息；
- 句首句尾无吞字，接缝无爆音；
- 字幕与实际发声起止对齐；
- 用户明确要求动效时，动效与对应关键词同时出现；
- 人脸、字幕和关键界面无遮挡；
- 输出比例与源片实际显示比例一致。

### 8. 单次正式导出

质量闸门通过后只正式渲染一次，输出到 `final/`。使用 H.264 + AAC、48kHz、faststart，并做探针、完整解码、代表帧和音频检查。平台未明确拒绝正式成片前，不额外转码上传版。

任务结束时把状态设为 `final_ready`，明确报告唯一正式文件路径。清理中间视频属于删除操作；必须列出精确路径、空间、恢复方式并获得用户确认，原片和唯一成片始终保护。

## 必须停止的情况

- 多段素材顺序无法从用户列表或文件名判断；
- 素材混合比例，且选择会改变构图；
- `ambiguous_cuts` 非空；
- 源片损坏或没有可用主音频；
- 代表帧与旋转元数据矛盾；
- 用户要求的视觉参考尚未提供。

其他情况按默认值继续，不反复询问。

## 交付口径

向用户只汇报：剪掉了什么、字幕与人声是否同步、可选动效是否启用、唯一成片路径、质量检查结果，以及是否仍有待确认的语义剪点。不要把缓存、中间工作片或渲染尝试数量包装成多个“视频版本”。
